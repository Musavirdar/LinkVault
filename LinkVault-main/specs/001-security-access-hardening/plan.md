# Implementation Plan: Security, Access Control & Quality Hardening

**Branch**: `001-security-access-hardening` | **Date**: 2026-10-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-security-access-hardening/spec.md`

---

## Summary

Eliminate a suite of security vulnerabilities in LinkVault's ASP.NET Core 8 backend: remove the unauthenticated static `/uploads` file server and replace it with an authenticated download endpoint supporting both Bearer JWT and single-use short-lived tickets; enforce organization tenancy and `CanShare` policy on share link creation; apply a dedicated strict rate-limiter to credential endpoints; validate uploaded file content via magic byte inspection (with SVG forced to attachment); fail-fast on insecure JWT secrets at startup; restrict audit log access to Admins only; fix the nullable `DirectoryId` sentinel bug; remove legacy packages; and add an automated test project + CI pipeline.

---

## Technical Context

**Language/Version**: C# / .NET 8.0 (ASP.NET Core 8)

**Primary Dependencies**:
- Entity Framework Core 8 + Npgsql — database ORM and PostgreSQL driver
- `Microsoft.AspNetCore.RateLimiting` — built-in rate limiting (already registered, not yet applied)
- `Microsoft.AspNetCore.Authentication.JwtBearer 8.0` — JWT auth middleware
- `Microsoft.AspNetCore.Mvc.Testing` + xUnit + Moq — test infrastructure (new)

**Storage**: PostgreSQL 15 via Docker Compose; local filesystem via `LocalStorageProvider`

**Testing**: xUnit + `WebApplicationFactory<Program>` + Moq (new test project)

**Target Platform**: Linux container (Docker), also runs on Windows dev machines

**Project Type**: Web service (REST API + SignalR hubs)

**Performance Goals**: Download streaming must not buffer entire file in memory; use `Stream` pipe from `IStorageProvider.GetAsync` directly to `Response.Body`

**Constraints**:
- No new external packages beyond xUnit/Moq for tests
- EF Core migrations must be additive (backward-compatible with existing data)
- Static file mount removal must not break any existing frontend route — frontend must be updated to use the authenticated endpoint

**Scale/Scope**: Single-tenant dev deployment; changes are scoped to the `backend/` project

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|--------------------------------------|
| New `DownloadTickets` DB table | Browser downloads cannot send `Authorization` headers; tickets solve this without exposing long-lived JWTs | Query-string JWT leaks credential in logs and referrer headers |
| New `FilesController` instead of patching static files | Static file middleware runs before auth middleware in the pipeline; cannot be retrofitted with auth | Restructuring middleware order would break other static assets (wwwroot) |

## Design Decisions Log

| Decision | Rationale | Reference |
|----------|-----------|-----------|
| Ticket TTL = 60 s | Long enough for redirect-then-download; short enough to limit exposure | research.md §1 |
| Auth rate limit = 10 req/min | OWASP recommendation for login endpoints; current global limit (100/min) is 10x too loose | research.md §2 |
| SVG ? force attachment | Spec clarification session 2026-10-27; prevents stored XSS without blocking SVG uploads | spec.md Clarifications |
| Audit log ? Admin only | Spec clarification session 2026-10-27 | spec.md Clarifications |
| No Redis for rate limiting | Single-instance deployment; built-in in-memory limiter is sufficient | research.md §2 |
| `Guid?` for DirectoryId | NULL is the correct FK semantics for "no parent"; Guid.Empty is a silent sentinel bug | research.md §7 |
